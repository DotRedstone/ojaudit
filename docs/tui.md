# TUI（第 6—7 阶段实现）

入口为 `python -m ojaudit.tui.app`，不修改现有 CLI；待第 5 阶段入口合并后再对接默认命令。使用 Textual 的一层一屏 Screen 栈，采集与检测数据只读自本地 SQLite，不访问 OJ。人工线索复核和人员标记仅通过核心 Store 写入专用表，不会覆盖分析结果。

## 导航

```text
首页
└── 比赛列表（按本地正则黑白名单过滤；a 切换显示全部）
    └── 比赛总览（当前分析轮次的线索数、选手数、题目数、提交数）
        ├── 线索 → 证据（插件分数、理由/时间线、左右代码与 diff）
        ├── 选手 → 选手详情 → 题目 → 提交历史 → 代码
        ├── 题目 → 所有人的代表代码 → 代码
        └── 排行榜（第 8 阶段）
```

首页的打开比赛 ID、账户/登录、设置入口暂为提示，不触发业务操作。总览下的排行榜入口保留给第 8 阶段。列表筛选直接复用 [核心筛选规则](data-model.md)，黑名单优先；切换全部模式会标注“规则外”，不修改配置。

## 按键与视觉

- `Enter` / `l`：进入当前项；`Esc` / `h`：返回上层。
- `j` / `k`：上下；`g` / `G`：首尾。
- `a`：在比赛列表切换筛选/全部；`?`：帮助提示；`q`：退出。
- 证据页 `Tab`：左右代码对照 / unified diff；`r`：线索三态复核（已核查、无需跟进、需进一步核实），保存后自动进入下一条待复核线索；`u`：切换待标记的左右选手，`m`：标记正常/存疑/作弊者与备注。
- 选手详情和代码页的 `m` 同样修改人员级标记，返回选手列表时读取最新标记；管理者显示“管理”且禁止打标。
- 题目详情 `s`：按 AC 时间、姓名、线索数量循环排序；代码页 `n/p`：在当前代码集合内前后移动，`[` / `]`：同一选手同一题目的历史提交前后移动。
- 已失效复核线索显示“已失效”，只能查看，不能写入新的复核状态。
- 顶部显示面包屑；主窗格为圆角边框与边框标题，聚焦时边框高亮；底部状态栏显示模式、当前对象、任务状态（本阶段固定空闲）和主题标签。
- 语义颜色定义在 `src/ojaudit/tui/palette.py`。任务进度订阅与更多主题仍留给后续阶段；证据等级使用 palette 语义色。

## 本地数据与验证

默认只读 `~/.local/share/ojaudit/ojaudit.db`（可通过 `XDG_DATA_HOME` 更改根目录）；数据库不存在时显示空列表，不创建库。可通过 `AuditApp(LocalContests(db_path, contest_filter))` 注入数据源用于测试。用户筛选规则从 `~/.config/ojaudit/config.toml` 加载；无规则时显示全部。

运行 `ruff check .`、`ruff format --check .`、`pytest -q`；`tests/tui/test_shell.py` 和 `tests/tui/test_review.py` 用合成 SQLite 数据与 `App.run_test()`/Pilot 测试导航、复核、标记同步和代码跳转。

## 数据与接口边界

- `review_data.py` 仅执行绑定参数的本地查询；人员标记和线索复核调用 `Store.put_person_mark` / `Store.put_finding_review`，不直接写业务表。
- 代表代码按最高分、同分最长代码、再按提交时间与 ID 排序选出；历史提交包含非 AC 状态。
- 当前分析以最新 `analysis_runs.created_at` 为准，旧复核的线索键若不在当前结果中则标记“已失效”。旧分析的复核状态不会自动归到新 run。
- 证据评分和理由直接显示分析结果 `scores` / `reasons` 的 JSON 数据；若没有单独的时间线详情，则不会凭空生成。
- 新的详细证据时间线结构、历史失效线索的独立持久化索引与更精细的权限接口仍依赖核心层后续扩展，本阶段只做已有字段可支持的展示。

后续阶段与 PR 状态统一见 [roadmap](roadmap.md)。
