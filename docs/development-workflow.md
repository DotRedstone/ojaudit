# 开发流程与 TODO 管理规范

本文细化项目任务说明第 1.8 节；阶段划分以 [roadmap.md](roadmap.md) 为唯一进度来源。

## 适用原则

- 简单改动保持简单；仅多步骤且需要交接或审查的工作使用临时清单。
- 不把临时日志、单次任务 TODO 写入长期架构文档。
- 设计未定时，在 `docs/` 编写标注“草案”的设计文档；定稿后移除标记，废弃方案直接删除。

## 阶段进度

- `docs/roadmap.md` 是阶段进度唯一来源，逐阶段列出复选框和对应 PR 链接。
- 只有阶段 PR 合并时，才能在同一变更中勾选该阶段。
- 其他文档仅链接 roadmap，不复制阶段状态。

## GitHub Issues

- 跨 PR 遗留问题、已知限制的后续改进使用 GitHub Issues。
- Issue 添加对应作用域标签，例如 `detector`、`tui`、`source-nowcoder`。
- 代码任务注释必须引用真实存在的 Issue 编号。

## 代码注释

允许的格式仅为：

```python
# TODO(scope): 中文说明 —— #123
# FIXME(scope): 中文说明 —— #123
```

- 必须有小写作用域、中文说明和 Issue 编号；禁止裸 `TODO`、`XXX`、无说明的 `FIXME`。
- `FIXME` 只描述已知错误行为；功能缺口使用 `TODO`。
- 注释可独占一行或作为行尾注释，但格式必须完整。
- 每个 PR 的任务报告列出新增的 TODO/FIXME；没有则明确写“无”。
- CI 执行统一格式检查，拒绝不合规的任务注释。

## PR 临时清单

跨步骤的临时清单只放在 PR 描述中，以复选框表达；合并后不迁入仓库长期文档。
