# TUI

入口为 `ojaudit`（无子命令）或 `python -m ojaudit.tui.app`。界面只读本地 SQLite，不在浏览时访问 OJ；人工复核和人员标记仅通过核心 `Store` 写入专用表，不覆盖分析结果。

## 页面结构

每个全屏页面由同一套外壳组成：

```text
 首▕比▕ 页面标题   副标题（数量、筛选、来源说明）
 页▕赛▕ 表头 …
   ▕列▕ 列表 / 内容 …
   ▕表▕
 ↵ 打开   ← 返回   / 搜索   ? 帮助               ● 下载源码 120/600 …  ← 提示栏 + 后台任务状态
```

- 页面是一层压一层的书页：上层页面收成左侧的窄书脊，竖排显示页名（开启 Nerd Font 时顶部带图标），离当前页最近的一条加粗。点击任意一条书脊直接翻回那一页；首页没有书脊。

- 提示栏只放当前页最常用的 4–6 个操作；按 `?` 打开帮助弹窗，它根据当前页面的按键绑定自动列出全部操作。
- 列表以对齐的表格行呈现，宽度按终端单元格计算（中文占两格）；单击只选中，双击或 `→` 打开。
- 颜色全部来自当前主题：等级 实锤 / 中偏强 / 存疑 分别使用主题的 error / warning / accent 色；`high/medium/low` 与之等价。
- 弹窗为 lazygit 风格：标题写在上边框，可用按键写在下边框，没有按钮、不遮挡背后的页面；`Enter` 确认、`Esc` 取消。输入框带实时校验（如比赛 ID、正则），不合法时 `Enter` 不会关闭。是/否确认用 `y` / `n`，`Enter` 选择安全的一侧。
- 搜索为 nvim 风格：按 `/` 在屏幕底部输入，边输入边跳到第一处匹配，`Enter` 停留、`Esc` 回到原位置。
- 分栏可以拖动调整宽度（首页、证据代码对照、设置、排行榜）：按住左栏的右边框、右栏的左边框或两者之间的空隙拖动，不额外画分隔线；双击空隙恢复默认，宽度记在配置 `[layout]` 中。
- 全部操作都可以只用鼠标完成：底部提示栏与弹窗底部的提示行显示「按键 说明」，每一项也都能直接点击；点击弹窗外部即取消；列表单击选中、双击打开；表头点击排序；设置页双击即编辑或切换。

排版原语（列对齐、徽章、进度条、提示栏）在 `src/ojaudit/tui/ui.py`，弹窗与搜索行在 `popup.py`，分隔条在 `splitter.py`，样式集中在 `themes/nowcoder.tcss`。

## 导航

```text
首页（菜单 + 概况 + 最近比赛）
├── 比赛列表（a 切换 全部/按规则筛选，c 采集，R 重新分析所选，x 取消任务）
│   └── 比赛总览（统计卡片；c 重新采集，R 重新分析）
│       ├── 线索 → 证据（指标、时间线、A/B 代码对照或差异）
│       ├── 选手 → 选手（各题提交与线索）→ 提交历史 → 代码
│       ├── 题目 → 代表代码 → 代码
│       └── 排行榜（策略、预览、导出）
├── 待复核（跨比赛的未处理线索与存疑选手）
├── 打开比赛 ID / 采集新比赛
├── 账户与登录
└── 设置
```

## 键位

| 意图 | 键盘 | Vim | 鼠标 |
|---|---|---|---|
| 同一层中上下移动（列表项、上/下一条证据或代码） | ↑ / ↓ | j / k | 滚轮、单击选中 |
| 进入下一层 | → | l | 双击 |
| 返回上一层 | ← / Esc | h；子页面 q | 单击左侧书脊 |
| 复核（可复核的页面）；其他页面同「进入」 | Enter / Space | — | 双击 / 点击提示栏 |
| 首项 / 末项 | — | g / G | — |
| 搜索当前列表 | / | / | — |
| 调整分栏宽度 | — | — | 拖动分隔线，双击复原 |
| 帮助 / 切换主题 | ? / t | ? / t | — |
| 退出 | 首页 q、Ctrl+C、Ctrl+Q | 首页 q | — |

各页面的专用键：

- 线索列表：`f` 循环 全部 → 高优先级 → 未处理 → 已处理（高优先级 = 实锤与中偏强）。列表按等级排序，证据页翻页使用同一顺序。
- 证据：`↑/↓`（或 `j/k`、`n/p`）上下一条，`Enter` 复核，`Tab` 在 A/B 对照与统一差异之间切换，`g/G` 首末条。
- 选手：`Enter` 复核此人，`→` 查看提交历史。
- 代码：`↑/↓` 上下一份，`[` / `]` 同人同题的前后提交，`Enter` 复核此人。
- 题目代表代码：`s` 切换排序（通过时间 / 姓名 / 线索数）。
- 排行榜：默认导出 Excel；作弊者可选「标记」（保留名单，作弊者整行标红）或「除名」（不出现在名单中，名次重新编号）。「未提交者」可选保留或剔除（剔除只报名、一次都没提交的人；0 分但提交过的人保留）。在右侧预览中选中某人按 `a` 即可设为 / 取消管理者（选手页同样可用），管理者按「管理者」策略剔除或标记，也不参与检测。`Enter`（或 `→`）切换当前策略取值，`Tab` 在策略与预览之间切换，`e` 导出，`←` 返回。
- 设置：`h`/`l` 或 `Tab` 切换左右栏，`Enter` 编辑（枚举弹出选项菜单），`Space` 切换开关、循环枚举或启用/停用规则，`a` 添加规则或管理者，`d` 删除，`r` 恢复本类默认，`Ctrl+S` 保存；未保存离开时确认（`y` 放弃、`n` 继续编辑）。
- 比赛列表：`S` 同步你参加过的比赛，`a` 显示被过滤规则隐藏的比赛；对「未采集」的比赛按 `Enter` 会询问是否采集。

## 证据页

- **线索面板**：等级、题号（A、B…）与题目、语言、复核状态；右上角「↗ A 提交 / B 提交 / 题目 / 比赛」可点击，直接在浏览器打开牛客页面（也可按 `o` 选择）。下面三行分别是各项相似度（≥90% 红、≥75% 橙）、时间线（谁先通过、相差多久、后者是否在对方通过后才首次提交）与依据（是否完全一致、同码人数、共享稀有片段数）。
- **代码对照**：左右按行对齐（缺行处画斜线补齐），两侧不同的行标黄并把行内具体不同的字符加深，只有一侧有的行标红 / 绿；左右两栏同步滚动，底部给出相同 / 不同 / 单侧行数。`Tab` 切换到全宽的统一差异视图。
- **视图开关**（只影响显示，可任意组合，记在配置 `[evidence]` 中）：
  - `f` 统一格式：统一运算符两侧空格、逗号后空格、4 空格缩进与大括号位置；
  - `c` 去注释；
  - `i` 忽略头文件、`using namespace`、`import` 与 IO 加速样板；
  - `v` 变量对齐：按代码结构把 B 的变量名换成 A 中对应的名字，被换名处加下划线；
  - `a` 全部开 / 全部关。点击视图栏上的开关同样有效。
  这样只是改了空格、缩进或变量名的抄袭会显示为完全相同。
- **复核**：只有一个入口，按 `Enter`。选项为「作弊 · 双方 / 作弊 · 仅 A / 作弊 · 仅 B / 存疑 / 正常 / 撤销复核」，可附备注；选了任何结论的线索即为已处理。双方的人员标记随结论自动更新（作弊只落在被认定的一方；存疑、正常不会冲掉已认定的作弊者），撤销后回到待复核、标记按其余结论重新推出。默认保存后自动跳到下一条待复核线索；认定某人作弊时，此人其余待复核线索一并处理，撤销该结论时这些线索也自动恢复（设置 › 复核 中可分别关闭这两项）。已失效线索只读。
- 选手页与代码页同样按 `Enter` 直接复核这名选手（作弊 / 存疑 / 正常 / 撤销复核）。
- 人名在所有列表与证据页中按人工标记着色：作弊者偏红、存疑偏黄、正常偏绿、管理者灰。

## 列表与排序

- 所有表格点击表头即按该列排序，再点切换升降序；`s` 循环切换排序列。
- 线索列表与复核面板默认按**嫌疑度**降序：同一对选手所有线索的分级之和（实锤 3、中偏强 2、存疑 1），同一对选手的多道题排在一起，便于一次判断。证据页翻页沿用列表顺序。
- 首页「待复核」为跨比赛的复核面板，分「待处理 / 已处理 / 全部」（`f` 或点击切换）。
- 题号统一显示为 A、B、C…，与比赛页面一致。

## 采集与分析

采集时底部提示栏右侧显示阶段、进度条、完成数与预计剩余时间，例如「下载源码 1234/8690 14% 剩余约 9:30」。按 `x` 或点击该任务状态可取消；取消、Ctrl+C 退出或程序异常退出时，尚未开始的源码请求都会被丢弃，正在进行的请求最多 20 秒内结束，不会在后台继续下载。


- 采集、入库和分析复用 Source、`import_bundle` 与 CLI 的 `_analyze`，在后台线程执行，不阻塞浏览；提示栏右侧显示当前阶段。
- 取消会在安全的步骤边界停止；正在进行的网络请求或数据库事务不会被强制中断。
- 界面不回显 Cookie 或异常详情。打开本地不存在的比赛 ID 时，显示采集引导页。

## 账户与比赛列表

「账户与登录 → 扫码登录」在程序内弹出二维码（半块字符绘制，黑码白底，任何主题下都能扫），微信扫码确认后自动保存 Cookie 并识别牛客 UID，`Esc` 取消、`r` 刷新二维码。也可以粘贴 Cookie，或用 `ojaudit login --qr` 在终端里扫码。Cookie 只保存在本机 0600 文件，不显示在界面、截图或日志中；扫码地址只在本地生成二维码，不发给任何第三方服务。

登录后，每次打开比赛列表会在后台同步一次你参加过的全部比赛（`S` 可手动刷新），以当前登录的账号为准：已采集的比赛不受影响；新比赛登记为「未采集」；只登记过、没有任何采集数据且已不在牛客返回列表中的比赛会被移除。按开始时间倒序排列，名称中的 HTML 实体（如 `&quot;`）会被解码。对「未采集」的比赛按 `Enter` 确认后即开始采集并检测。

## 设置

分类：账户、过滤规则、采集、检测、外观、插件、关于。修改项前有 `*`，下方显示说明与默认值；只有 `Ctrl+S` 写入配置。

**过滤规则**合并了原来的比赛筛选与人员名单：

- 过滤模式：黑名单（默认，隐藏命中的比赛）或白名单（只显示命中的比赛，没有启用的规则时显示全部）。默认没有规则，即显示全部比赛。
- 比赛规则：每条一个 Python 正则，可逐条启用/停用。输入时下边框实时显示命中的本地比赛数，正则写错会直接提示。
- 管理者：输入「UID 备注」，管理者不参与检测、排行榜中默认剔除（保存在数据库 `hidden_people`）。
- 旧版配置的 whitelist / blacklist 两组列表会被自动读取，保存时转为新格式。

**外观**的修改即时预览，放弃修改时恢复：

- 主题：auto（有 pywal / matugen 配色时跟随壁纸）、wallpaper，以及 Textual 自带的全部主题（tokyo-night、dracula、rose-pine、solarized、catppuccin 等）。`ansi-dark` / `ansi-light` 使用终端自身的 16 色与背景。
- 透明背景：使用终端背景色，与 nvim / lazygit 的透明终端一致；此时代码高亮自动改用终端配色。
- 边框样式：圆角、直角、粗线、双线、ASCII。
- 代码高亮配色、代码行号、底部按键提示、Nerd Font 图标。

配置文件被外部修改（例如手动编辑 `config.toml`）时，外观会在 2 秒内自动重新加载；壁纸配色文件变化同样会热更新。

其他：采集配置 `collect.*` 由 CLI 与 TUI 共用；检测参数按各阶段清单生成控件并校验，必需阶段只读；配置中不保存 Cookie。

## 排行榜

策略：作弊者「剔除/标记」，存疑者「照常/标记/剔除」，管理者「剔除/标记」；格式 Markdown / CSV / HTML。预览由核心 `build_final_ranking()` 计算，待复核线索与未标记人员只提醒、不阻止导出。

数据库没有官方名次和罚时，榜单按本地每人每题最高分推算，始终标注「非官方」。导出到 `$XDG_DATA_HOME/ojaudit/exports/<platform>/<contest_id>/ranking.{md,csv,html}`；CLI 与 TUI 使用同一推导算法。

## 主题与图标

- `t` 循环切换全部主题（只在本次运行生效，设置 › 外观 可保存）。壁纸配色读取 `OJAUDIT_THEME_FILE`、`~/.cache/wal/colors.json`、`~/.cache/matugen/colors.json`、`~/.config/matugen/colors.json`，只接受校验过的十六进制颜色，不执行 pywal/matugen，不注入 CSS；无有效文件时回退到 catppuccin-mocha。
- Nerd Font：码位只在 `src/ojaudit/tui/icons.py` 定义；关闭后不输出 U+E000–U+F8FF 字符。

## 本地数据

数据库路径优先级：`--db PATH` > 配置 `[storage] sqlite_path` > `$XDG_DATA_HOME/ojaudit/ojaudit.sqlite`。TUI 只读打开，数据库不存在时显示空列表并提示 `ojaudit login → ojaudit collect <比赛ID> → ojaudit analyze <比赛ID>`；后台任务正在创建数据库时按空库处理。

- `review_data.py` 只执行绑定参数的本地查询；写入只调用 `Store` 的人员标记与线索复核接口（含撤销用的 `clear_person_mark` / `clear_finding_review`）。线索结论在库中仍存为 已核查 / 需进一步核实 / 无需跟进，界面分别显示为 作弊 / 存疑 / 正常，CLI 不受影响。
- 代表代码按最高分、同分最长代码、再按提交时间与 ID 选出；提交历史包含未通过提交。
- 当前分析以最新的 `analysis_runs.created_at` 为准；同一线索键的复核会沿用到新轮次，旧轮次独有的线索标记为「已失效」。

## 验证

`ruff check .`、`ruff format --check .`、`pytest -q`。TUI 测试使用合成 SQLite 与 `App.run_test()`/Pilot 覆盖导航、复核、标记同步、代码跳转、设置与排行榜；不包含真实比赛、UID、Cookie 或选手代码。
